# 磊毛阅读

> 一款能导入小说、漫画、视频源，也能订阅 RSS 的安卓阅读器

**待完成清单 / 开发路线：[TODO.md](./TODO.md)**

**磊毛阅读**是一款支持自定义导入书源的聚合类安卓阅读 App，统一支持 **小说 / 漫画 / 视频** 三大内容形态。用户可自由导入 JSON 源、JS 源、兼容「阅读 (legado)」标准书源、**Venera 漫画源**（含 `index.json` 源集合一键批量导入）以及 **MoonTV / LunaTV 采集源**（订阅链接一次导入几十个视频源），实现一站式的阅读、追漫、看片体验；视频模块自带 **MoonTV 风格首页**（继续观看 + 分类分区横滑 + 海报墙），此外还内置 **RSS 订阅**模块，可订阅博客 / 资讯站，把推送内容当文章读。

## 核心特性

| 能力 | 说明 |
|------|------|
| 源导入 | 支持 JSON 源 + JS 源 + 阅读(legado) 书源 + Venera 漫画源（含 `index.json` 批量导入）+ **MoonTV/LunaTV 采集源**（订阅链接或配置 JSON，一份配置展开成多个视频源），含 txt 网址书源，支持本地文件选择与链接在线下载（带进度） |
| 小说阅读 | 字体大小可调、背景色可选、白天/夜间双模式、章节缓存下载 |
| 漫画阅读 | 完美适配屏幕、翻页方式可切换（上下滚动/左右翻页）、滚到边界继续拖即切上一话/下一话、图片缓存下载 |
| 影视首页 | 视频 Tab 的「首页」视图（MoonTV 风格）：**继续观看**（时间进度条 + 看到第几集，点击续播）+ **各一级分类各一排横滑**（「查看更多」进入分类海报墙，带触底分页）+ 站点源选择 + 胶囊切换 + 骨架屏 + 评分角标，当前源记忆；「收藏」视图保留原书架 |
| 视频播放 | 支持视频目录（选集）、播放进度记录、视频下载；**窗口 / 全屏双态**（全屏横屏沉浸式）、**长按右半屏 3x 快进 / 左半屏快退**、双击左右 ±10 秒、横滑调进度、左竖滑亮度 / 右竖滑音量、0.5x~3x 倍速（记忆）与播完连播 |
| 播放增强 | 多线路「选集 / 换源」双 Tab + 线路测速择优、HLS 多码率清晰度切换、外挂字幕（srt/vtt/ass/ssa）、画中画小窗、边播边缓存 |
| 短剧 | 竖屏沉浸上下滑、海报直进全屏、红果式选集浮层、竖横屏切换 |
| 标签体系 | 从标题 / 简介自动收集标签，支持单词、复合（严格交集）与多语言同义标签搜索，热门标签推荐 |
| 云备份 | WebDav 上传 / 下载 / 测试连接，备份含书源、书架、阅读进度与书签 |
| RSS 订阅 | RSS 2.0 / Atom / RDF 三种格式统一解析，支持网页自动发现订阅地址与 OPML 批量导入；未读计数、已读标记、收藏、上一篇/下一篇连读、离线可读（正文已入库） |
| 搜索 | 三类内容均支持站内搜索，跨源并发搜索 + 实时进度展示 + 模糊搜索 + 搜索历史 |
| 源管理 | 源智能分类、类型筛选、排序、列表/表格双视图 |
| 书架 | 收藏管理、阅读进度记录、继续阅读 |

## 技术栈

- **语言**：Kotlin
- **UI**：Jetpack Compose
- **架构**：MVVM + 分层（Core / Source / Domain / Data / UI）
- **JS 引擎**：Rhino 1.7.15（兼容 legado/阅读 JS 源）；**隐藏 WebView (V8)**（承载 Venera 源，其依赖 class 字段 / async-await，Rhino 不支持）
- **网络**：OkHttp + Retrofit
- **数据库**：Room
- **图片**：Coil
- **视频**：Media3 (ExoPlayer)
- **偏好设置**：DataStore

## 版本规范

版本号为**四段式**：`顶端版本.大版本.小版本.修订`（如 `1.3.2.0`）。

| 段位 | 何时 +1 | 说明 |
|------|---------|------|
| 顶端版本 | 每十个大版本 | 进位时大版本归零 |
| 大版本 | 每十个小版本 | 进位时小版本归零 |
| **小版本** | **每发一版** | 日常发版只动这一位（`0~9`） |
| 修订 | 同一小版本内打补丁 | 日常保持 `0` |

递增示例：

```
1.3.0.0 → 1.3.1.0 → 1.3.2.0 → 1.3.3.0 → 1.3.4.0 → … → 1.3.9.0   （小版本走满十个数）
        → 1.4.0.0 → … → 1.9.9.0             （大版本走满十个数）
        → 2.0.0.0                            （顶端版本 +1）
```

`versionCode = 顶端版本 × 1000000 + 大版本 × 10000 + 小版本 × 100 + 修订`

发版时四处同步：`app/build.gradle.kts`（`versionCode` / `versionName`）、`AppVersion.CURRENT_VERSION`、`CHANGELOG.md` 与 `AppVersion.CHANGELOG` 顶部条目、git tag `v顶端.大.小.修订`。

> 历史遗留与重排：早期版本号曾在第 3 / 第 4 位递增（`1.0.x`、`1.1.x`、`1.2.x`，其中 `1.2.10` / `1.2.11` 已超出两位），之后 `1.3.0`~`1.5.0` 又跳到第 2 位。现已**全量重排为四段式**：`1.0.x` 原样保留，`1.1.x` / `1.2.x` / `1.3.0` 补全第四段（如 `1.2.11 → 1.2.11.0`），原 `v1.4.0 → v1.3.1.0`、`v1.5.0 → v1.3.2.0`。GitHub 上的 tag / Release / APK 与本仓库代码、CHANGELOG 均已同步。**当前版本以 `AppVersion.CURRENT_VERSION` 为准**（不再在 README 里硬编码，避免过期）。

## 如何构建

1. 使用 Android Studio 打开本目录
2. 等待 Gradle 同步完成
3. 运行到设备或模拟器（minSdk 24，即 Android 7.0+）

> 注意：首次构建需联网下载依赖，Rhino 来自 jitpack 仓库。

  换机 / 重装系统后 `git clone` 即可直接 `assembleRelease`，不会再出现密钥丢失导致无法覆盖升级。

- **换签历史**：2026-10-18 原密钥（旧指纹 `8ea0d34e5ddeeb2aa4ae2801572ccdf46c6eba002274a93208660774d3d147f2`）
  在本机/GitHub 均已无备份，确认无法恢复，故启用上述新密钥。**从 1.8.1.0 起签名已变，
  已装旧版的设备必须先卸载再安装**（数据会清空，升级前先导出备份）；装过 1.8.1.0 之后的版本可正常覆盖升级。
- 构建：`gradle assembleRelease` → 产物 `app/build/outputs/apk/release/`（已签名，v2 方案）。
  **v1.8.1.4 起按 ABI 拆分**（ONNX Runtime 的 native 库每个 ABI 约 18MB，四合一会到 88MB）：
  `app-arm64-v8a-release.apk`（~35MB，真机默认）、`app-armeabi-v7a-release.apk`（~30MB，32 位老设备）、
  `app-x86_64-release.apk`（~38MB，模拟器）、`app-universal-release.apk`（~88MB，全 ABI 兜底）。
- 发版前必检：`apksigner verify -v app-arm64-v8a-release.apk`，必须看到 `Verified using v2 scheme (APK Signature Scheme v2): true`，

- **发版前必须在模拟器实际安装验证**（用户明确要求）：启动 `legado_test` AVD → `adb install app-release.apk` → 拉起 MainActivity 确认首页正常渲染。若模拟器上残留旧包且签名不同会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，先 `adb uninstall com.novelreader` 再装。

- 若 `keystore.properties` 缺失，构建会退化为**未签名**（`app-release-unsigned.apk`）——这种包**装不上**，禁止发布。

## 核心设计

**适配器模式**：上层只依赖 `SourceAdapter` 接口，JSON 源、JS 源、legado 书源各自实现，新增源格式只需新增一个 Adapter，无需改动上层代码。
