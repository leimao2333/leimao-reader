# 构建与运行指南（阅读神器 NovelReader）

本文档指导你在 Android Studio 中构建、运行本项目，并说明常见问题与真机调试步骤。

## 一、环境要求

| 项目 | 要求 |
|------|------|
| Android Studio | Ladybug (2024.2.1) 或更新版本 |
| JDK | 17（项目 `jvmTarget = "17"`） |
| Android SDK | compileSdk 35 / minSdk 24 / targetSdk 35 |
| Gradle | 8.x（随项目 wrapper 提供） |
| 网络 | 首次构建需联网下载依赖 |

## 二、在 VS Code 中构建与运行

1. 使用 VS Code 打开项目根目录。首次打开时，按提示安装工作区推荐扩展：Kotlin、Gradle for Java、Android、Java 和 Java Debugger。
2. 确认已安装 JDK 17 和 Android SDK Platform 35。若 SDK 未自动识别，在项目根目录的 `local.properties` 中设置 `sdk.dir`（该文件已被 Git 忽略）。
3. 使用 `Terminal → Run Task` 执行 **Android：构建 Debug APK**；也可按 `Ctrl+Shift+B`。APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。
4. 连接已开启 USB 调试的 Android 设备或启动模拟器，然后按 `F5`，选择 **Android：启动磊毛阅读**；VS Code 会先构建 APK，再安装并启动应用。也可在 `Terminal → Run Task` 执行 **Android：安装到已连接设备**。

VS Code 任务使用项目的 Gradle Wrapper；首次构建会下载 Gradle 和项目依赖。若没有连接设备，构建 APK 仍可正常进行，但安装任务需要设备或模拟器。

## 三、Android Studio 构建步骤

1. **打开项目**
   - 启动 Android Studio → File → Open → 选择 `NovelReader/` 目录
   - 等待 Gradle Sync 完成（首次同步需下载 Compose、Rhino、Media3、Room 等依赖）

2. **配置 SDK**
   - 若提示 SDK 缺失，在 `local.properties` 中配置：
     ```
     sdk.dir=C\:\\Users\\<你的用户名>\\AppData\\Local\\Android\\Sdk
     ```
   - 或通过 Android Studio 的 SDK Manager 安装 Android 14 (API 35) 平台

3. **同步与构建**
   - 点击 Sync（或 `File → Sync Project with Gradle Files`）
   - 构建 Debug 包：`Build → Make Project`（或命令行 `./gradlew assembleDebug`）

4. **运行**
   - 连接真机或启动模拟器（Android 7.0 / API 24 及以上）
   - 点击 Run（绿色三角）或 `./gradlew installDebug`

## 五、首次运行体验（功能闭环）

1. **导入源**：首页 → 源管理 → 导入源 → 从文件选择或粘贴源码（JSON/JS）
   - 样例源见项目 `samples/json/` 和 `samples/js/`
2. **搜索**：首页 → 小说/漫画/视频 → 输入关键词
3. **阅读/播放**：点击结果 → 详情 → 章节/选集 → 阅读页/播放页
4. **收藏**：详情页点击收藏 → 书架查看
5. **继续阅读**：书架点击 → 直达上次章节
6. **设置**：首页 → 设置 → 日夜间 / 字体 / 背景 / 翻页方式

## 六、常见问题（FAQ）

### 1. Gradle Sync 失败 / 依赖下载慢
- 检查网络，或为 Gradle 配置镜像（`~/.gradle/gradle.properties` 添加阿里云镜像）
- 清理缓存后重试：`File → Invalidate Caches / Restart`

### 2. Rhino 依赖找不到
- 确认 `settings.gradle.kts` 的 `repositories` 含 `mavenCentral()`
- 确认依赖写法为 `org.mozilla:rhino:1.7.15`（注意是 `org.mozilla` 而非 `org.mozilla.javascript`）

### 3. Room 编译报错（kapt）
- 确认 `app/build.gradle.kts` 中已应用 `kotlin-kapt` 插件
- 确认实体类有 `@Entity` 注解、DAO 有 `@Dao` 注解

### 4. Media3 播放报错
- `VideoPlayerViewModel` 使用 `@UnstableApi` 标注，需在模块级 `@OptIn(UnstableApi::class)` 或忽略
- 部分源需要防盗链请求头，已通过 `DefaultHttpDataSource.Factory.setDefaultRequestProperties` 注入

### 5. 中文乱码
- `HttpClient` 已实现字符集识别（Content-Type → HTML meta → GBK 回退），一般无需处理
- 若仍有乱码，检查源的 `charset` 声明是否与站点实际编码一致

### 6. 漫画图片不显示
- 部分站点图片需 Referer 防盗链，检查源的图片地址与 `headers` 配置
- Coil 加载失败时可在源的 `content` 规则中补充请求头

## 七、书源健康与响应速度诊断

手动运行真实书源探测（会向第三方站点发送搜索、目录和正文请求；默认不参与常规单测）：

```powershell
$env:LEIMAO_REAL_TESTS = "1"
$env:LEIMAO_HEALTH_LIMIT = "8" # 可选；省略或设为 0 会测试全部 legado 源
.\gradlew.bat :app:testDebugUnitTest --tests com.novelreader.SourceHealthProbeTest
```

默认书源清单为 `https://raw.githubusercontent.com/leimao2333/leimao-sources/main/all.json`。
测试会从聚合清单解析并下载 `legado-all.json`；可用 `LEIMAO_HEALTH_FILE` 指定本地源文件、
本地聚合清单（其同目录需有 `legado-all.json`）或其他清单 URL。报告包含搜索、发现、
详情/目录、正文各阶段及总耗时，写入 `app/build/source-health-report.json` 和 `.csv`，
并在测试输出中列出最慢的来源。默认先尝试源自身的发现分类，再按小说/漫画等类型使用
多个搜索词；单源没有匹配结果会标为「无法判定」，不再直接当作故障。每个 HTTP 请求由
OkHttp 总调用超时硬限制为 6 秒，避免阻塞式 IO 穿透协程超时。JSON 的 `summary` 汇总
配置记录数、唯一源名/配置数、重复源名、健康/无法判定/规则问题数，以及按偶数样本取
中间两值均值的总耗时中位数；逐源 JSON/CSV 以源名与地址、规则的稳定哈希 ID 标识。
默认并发为 8，可通过 `LEIMAO_HEALTH_CONCURRENCY` 调整；可用逗号分隔的
`LEIMAO_HEALTH_KEYWORD` 覆盖默认探测词。

## 八、真机调试要点

1. **网络权限**：`AndroidManifest.xml` 已声明 `INTERNET` 权限，确认未遗漏
2. **HTTP 明文流量**：若源为 HTTP（非 HTTPS），Android 9+ 默认禁止明文流量，
   需在 Manifest 的 `<application>` 加 `android:usesCleartextTraffic="true"`（当前默认允许，上线前应改用 HTTPS）
3. **JS 源调试**：可在 `SourceJsBridge` 中打开 `log` 输出（`adb logcat | grep SourceJsEngine`）
4. **数据库检查**：用 Android Studio 的 Database Inspector 查看 `sources`/`books`/`progress` 三张表
