# RSS 订阅模块（v1.4.0）

> 2026-10-13 · 磊毛阅读 v1.4.0

## 一、目标

应用原先只有「搜索型书源」（用户搜关键词 → 源返回结果）。RSS 订阅是**推送型**内容，
语义完全不同：用户订阅一个地址，源持续产出文章。本次把它做成独立模块，
而不是硬塞进 `SourceAdapter`。

## 二、为什么独立成模块（而不是复用书源体系）

| 维度 | 书源（legado 等） | RSS 订阅 |
|------|------------------|----------|
| 入口 | 关键词搜索 / 发现分类 | 订阅地址列表 |
| 产出 | 搜索结果 → 详情 → 目录 → 正文/图片/视频 | 文章流（时间倒序） |
| 资源标识 | sourceId + itemId + chapterUrl | feedId + article guid |
| 状态 | 阅读进度 / 书架 / 缓存 | 已读 / 未读 / 收藏 |
| 换源 | 有（同书多源） | 无（一源一订阅） |

硬套 `SourceAdapter` 会把「搜索/目录/换源」这些无意义语义拖进订阅链路，
所以新增 `RssRepository` + `rss_feeds` / `rss_articles` 两张表，与书源体系完全解耦。

## 三、分层实现

```
core/rss/
  RssParser.kt      # RSS 2.0 / Atom / RDF 解析 + OPML + 页面订阅地址发现 + 时间解析
  RssContent.kt     # 正文 HTML → 段落/图片块（懒加载图片属性、相对地址补全、丢弃 script/style）
domain/
  model/RssModels.kt        # RssFeed / RssArticle / RssFeedResult
  repository/RssRepository.kt
data/
  model/RssFeedEntity.kt    # rss_feeds（url 唯一）
  model/RssArticleEntity.kt # rss_articles（feedId + guid 唯一）
  database/RssDao.kt
  repository/RssRepositoryImpl.kt
ui/screens/rss/
  RssScreen.kt       # 订阅页：源 chips + 筛选 chips + 文章流 + 添加/管理弹窗
  RssReaderScreen.kt # 阅读页：段落+图片渲染、上一篇/下一篇、收藏、标未读
  RssFormat.kt       # 时间展示
```

## 四、关键设计决策

1. **抓取失败不抛异常，用 `RssFeedResult.error` 表达**
   批量刷新常见「几十个源里挂几个」，异常会打断整批；现在单个源失败只记录原因，
   界面上能看到「3 个失败」，其余源照常更新。

2. **增量入库靠唯一索引 + `INSERT OR IGNORE`**
   去重键 `(feedId, guid)`。若用 `REPLACE`，重新抓到的文章会把行删掉重建，
   **已读 / 收藏状态会被冲掉** —— 这是订阅类应用最常见的 bug，故显式使用 IGNORE。

3. **限流并发 3 路**
   订阅源动辄几十上百个，全量并发容易被目标站判定为爬虫。`Semaphore(3)` 控制。

4. **每源保留 300 篇**
   长期订阅（日更博客）会让库无限增长；`trimFeed` 在每次抓取后清理超量最旧文章。

5. **进入自动刷新（>30 分钟未抓取）**
   订阅类应用的核心预期是「打开就有新内容」，但又不能在每次重组时重复请求，
   因此用「过期判定 + 一次性标记」而不是「每次进页面都全量刷」。

6. **正文块模型（`RssBlock.Paragraph` / `Image`）**
   RSS 正文 HTML 来源极杂（WordPress `<p>`、微信式 `<section>`、老博客 `<div><br>`），
   直接 `Jsoup.text()` 会丢掉所有分段。改为「块级元素分段 + 图片独立成块」，
   阅读页渲染与小说阅读页同源（16sp / 行高 26sp）。

7. **恢复备份时重建 feedId 映射**
   订阅文章靠自增 `feedId` 关联；导入备份到新库时 id 会变，因此恢复时记录
   旧 id → 新 id 映射后再写文章，避免文章挂到别的订阅下。

## 五、数据库

v10 → v11，新增两表（含迁移，不影响存量数据）：

- `rss_feeds`：feedId(PK) / url(唯一) / title / siteUrl / description / iconUrl / groupName / sortOrder / lastFetchAt / lastError / createdAt
- `rss_articles`：articleId(PK) / feedId / guid / title / link / author / pubDate / summary / contentHtml / imageUrl / read / starred / fetchedAt，唯一索引 `(feedId, guid)`
