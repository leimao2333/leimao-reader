# 架构设计文档

## 一、总体架构

采用 **MVVM + 分层架构**，分为三层：

```
┌─────────────────────────────────────────────┐
│                  UI 层 (Compose)             │
│  screens / components / navigation / theme   │
├─────────────────────────────────────────────┤
│                Domain 层（纯业务）            │
│     model / repository接口 / usecase          │
├─────────────────────────────────────────────┤
│                 Data 层（数据实现）            │
│  source / repository / database / network    │
├─────────────────────────────────────────────┤
│            Core 层（基础能力，跨模块）          │
│     js引擎 / 网络 / 偏好设置 / 工具            │
└─────────────────────────────────────────────┘
```

## 二、核心模块说明

### 2.1 源解析引擎（source 包）

这是本项目的**核心**。设计为"加载 → 解析 → 统一"三阶段：

```
SourceLoader（源加载）
   ├─ JsonSourceLoader  → 解析 JSON 源
   └─ JsSourceLoader    → 通过 Rhino 解析 JS 源
        ↓
SourceParser（源解析）
   ├─ JsonSourceParser
   └─ JsSourceParser
        ↓
统一输出 → SourceInfo（统一中间模型）
        ↓
SourceManager（源管理，统一调度）
```

**关键设计：适配器模式**
- 定义 `SourceAdapter` 接口（统一的方法签名：search / detail / chapterList / content）
- `JsonSourceAdapter` 和 `JsSourceAdapter` 各自实现
- 上层只依赖 `SourceAdapter`，新增源格式只需新增一个 Adapter，**无需改动上层代码**

```
接口定义：
interface SourceAdapter {
    val info: SourceInfo
    suspend fun search(keyword: String, page: Int): List<MediaItem>
    suspend fun detail(url: String): MediaItem
    suspend fun chapterList(url: String): List<ChapterItem>
    suspend fun content(url: String): ContentResult
}
```

### 2.2 网络层（core/network）

- 统一 HttpClient（OkHttp），支持自定义 UA、Cookie、重试
- 响应统一封装，支持 gzip、字符集自动识别
- 为漫画/视频源预留"自定义请求头"配置能力（应对防盗链）

### 2.3 数据层（data）

- **Room 数据库**：存储书源、书架、阅读进度、搜索历史
- **Repository 实现**：实现 Domain 层定义的接口

### 2.4 UI 层（ui）

| 模块 | 说明 |
|------|------|
| theme | 主题，含日/夜间配色方案 |
| navigation | 统一导航路由 |
| screens/novel | 小说（搜索/目录/阅读/设置） |
| screens/comic | 漫画（搜索/阅读/翻页） |
| screens/video | 视频（搜索/目录/播放） |
| screens/settings | 设置中心 |
| screens/common | 通用（源管理、书架等） |

## 三、数据流

```
用户操作 → ViewModel → UseCase → Repository → SourceAdapter
                                            ↓
                                   网络请求 / JS 执行
                                            ↓
                                   统一中间模型
                                            ↓
                              StateFlow → UI 渲染
```

## 四、预留扩展点（冗余修改空间）

| 扩展点 | 位置 | 说明 |
|--------|------|------|
| 新源格式 | source/parser | 新增 Parser + Adapter 即可 |
| 新内容类型 | domain/model + ui/screens | SourceType 枚举扩展 |
| 新阅读设置 | core/preferences | DataStore 新增 key |
| 新网络协议 | core/network | 新增 Interceptor |
| 自定义规则 | source/engine | 预留规则引擎接口 |

## 五、目录职责对照

```
com.novelreader
├── core/              # 基础能力（js、network、preferences、util）
├── source/            # 源引擎（loader、parser、manager、engine）
├── domain/            # 业务层（model、repository接口、usecase）
├── data/              # 数据实现（model、repository、database、network、source）
└── ui/                # 界面（theme、screens、components、navigation）
```
