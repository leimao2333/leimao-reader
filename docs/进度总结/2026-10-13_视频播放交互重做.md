# v1.5.0 视频播放交互重做（全屏 / 长按快进 / 手势）

> 日期：2026-10-13 ｜ 参照对象：[sudizer/moontv](https://github.com/sudizer/moontv)（ArtPlayer 交互习惯）

## 一、背景与目标

播放页此前只有：

- `PlayerView` 默认控制条（`useController = true`）
- 画面固定 16:9、竖屏，**没有全屏**
- 唯一的手势是「长按 → 一次性 +10 秒」

目标是按 MoonTV（底层 ArtPlayer）的看片习惯重做：**全屏、长按倍速快进、双击快进快退、横竖滑手势、自定义控制层**。

### 关键实现细节

- **手势冲突**：`detectTapGestures` 与 `detectDragGestures` 挂在同一个 `Box` 的两条 `pointerInput` 上；拖动一旦超过 touch slop 由 drag 侧 `change.consume()`，tap 侧的 `waitForUpOrCancellation` 拿到被消费的变更后自动放弃，因此「单击显隐 / 双击快进 / 长按倍速 / 拖动调参」可共存。
- **进度条与拖动手势的分工**：底部进度条属控制层（在手势层之上），拖动它走 `Slider`；画面其余区域横滑走自定义手势层，两者不会打架。
- **快退实现**：ExoPlayer 不支持负倍速，故左半屏长按用「定时 `seekTo(-1s)`」协程模拟约 4x 回退，展示倍速取 4.0x。
- **倍速记忆的写入时序**：`videoSpeedFlow` 采集时若正处于长按加速中则不写播放器，避免把 3x 加速态覆盖成常规倍速。

### 测试基建修复

测试站的 `/video/test.mp4` 原先不支持 **HTTP Range**，ExoPlayer 拉流直接 `ProtocolException: unexpected end of stream`。已给 `server.py` 增加 `_send_range`（206 + `Content-Range` + `Accept-Ranges`），并把测试视频换成 991KB / 10s 的 faststart 片段（原 4.5MB 非 faststart 文件在模拟器 NAT 下仍会中断）。
